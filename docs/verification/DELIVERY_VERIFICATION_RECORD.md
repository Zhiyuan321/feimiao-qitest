# 当前交付的验证范围

## 交付路径

本次统一放在开发目录下 `07-当前交付/`：Windows7、macOS、源码各自独立。源码入口见 [维护地图](../architecture/CODE_MAINTENANCE_GUIDE.md)。不混入 SCIENTZ 项目或客户数据库。

## 已执行的验证方法

- Mac Release 构建及 8 组 Qt 自动测试：驱动回执契约、AI 生命周期、科学核心、AI 工具/证据、参考库、工作区、权限、UI。
- Windows Qt 5.12.12 原生 x64 交叉构建，同样 8 组测试在免费 Wine 11.0、Win7 前缀下运行。Wine 是兼容性检查，不是真实 Win7 硬件台架。
- UI：80 次导航后的控件数量不增长；方法激活、实际 PDF 文件、双栏窄屏/宽屏、输入框范围、图表事件与截图。Wine 的 offscreen 模式使用实际鼠标事件处理器测试悬停，不把 macOS 全局指针映射作为断言前提。
- 驱动：未授权不发送、真实操作确认、重复提交阻断、匹配回读、错序/迟到 ACK 丢弃、超时后状态未知。厂商模板在 Mac 与 Win7 两端独立编译；默认不连接硬件。
- AI：打开面板不会预热模型，不加载模型也能查说明；手动关闭、空闲卸载、重启、启动超时、请求超时、队列上限；测试使用轻量假服务，不反复加载 3GB 权重。
- 数据：186 条跨半年时间标签的完整小型测试记录，限量历史查询、重开与旧记录恢复、异常退出标志恢复、事务和 PDF。**这是有限回归样本，不是运行了半年，更不是百万条真实大谱图压测。**
- 发布目录和 ZIP：Qt5 DLL、插件、图标、每个子进程独立运行库依赖、PE x64、已知 Win7 后 API 静态导入、SHA256 和 ZIP CRC。该检查不是对所有 Windows API 的完整证明。
- Mac `.app`：arm64、资源、参考库完整性、模型哈希、Qt 插件、临时签名完整性及可见启动。

详细本机自动测试输出在开发机 `.qa/qt512-tests/`、`build-qt610/Testing/Temporary/LastTest.log`；构建与日志不进入源码 ZIP。最终包中的 `SHA256SUMS.txt` 对应实际发布目录，不沿用旧包清单。

## 真实模型的有限实测

本机 Wine / CPU 基线运行 Windows `llama-server.exe`，实际加载当前 Qwen Q4 并回答中文问题：

- 加载约 11.07 秒；测试总用时约 113.86 秒。
- 输入 86 token、输出 17 token，回答可读。
- 观察到 AI 子进程 RSS 约 3.11 GiB；此处是 Mac/Wine 观测，不是工控机 Windows 内存承诺。

这说明旧 CPU 兼容档可以运行模型，但复杂问答明显慢，不能宣称秒答。采用独立进程、低优先级、CPU 线程限制、默认关闭、常用操作绕过模型，保护主界面与核心工作流。内存不足时不强行加载，不静默给出不可靠仪器操作。
