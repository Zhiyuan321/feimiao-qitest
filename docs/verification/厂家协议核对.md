# 厂家通信协议接入评估

核对日期：2026-09-03。输入文件在项目根目录 `厂家参考/`，仅本地阅读，未对外上传，未连接设备或发送控制报文。

## 结论

两份协议可作为原生 C++ 设备适配器的开发依据，并非 SDK；有协议不一定还需要 SDK。但当前内容存在歧义，不能直接宣称硬件接入完成。不得根据猜测下发高压、放空、RF、泵或加热命令。Qt 5.12 架构可以保留；Mac 与 Windows 共用协议编解码，串口驱动及实际设备连接需要分平台核对。

## 能力对应

| 文件 | 已找到的协议能力 | 对应现有软件 |
| --- | --- | --- |
| 便携式质谱485通讯协议V2.1.pdf，第5-7页 | TD/离子阱温度、载气切换、EFC、气泵/进气泵 PWM、HV/RF 24V、隔膜泵、状态查询 | 参数预设、仪器开关、遥测显示 |
| 便携式质谱网口通讯协议1.4(最新版).pdf，第6-15页 | 检测启停、调谐、方法参数、RF 24/48V、高压、隔膜泵、放空、离子采集上传、气压上传、报警 | 采集与分析、方法编辑、仪器控制、时间序列 |

两路都有部分电源/泵命令，不能同时发送或假定是同一板卡，须确认各自控制对象及主从关系。两份协议不足以证明分子泵转速/电流/温度、注射泵余量、电池信息等所有界面数据均可获得。

### 新增辅助控制的逐项依据

仅保留原文明确列出的能力；协议存在命令不等于现场型号装配该部件，更不等于软件已完成实机通信。新入口位于现有仪器控制内部，不增加顶部菜单。悬停部件选择框可查看页码和命令编号。

| 界面名称 | 原文与来源 | 边界 |
| --- | --- | --- |
| 喷雾观察灯 | 485 第5页 `0x01 24V 激光灯开关`；第8页明确用于辅助观察 ESI 喷雾 | 不是电离激光器控制 |
| 风扇（FAN） | 485 第5页 `0x05 FAN 开关` | 原文未明确散热对象，不扩写为具体散热系统 |
| 废液泵 | 485 第5页 `0x06 废液泵开关` | 不推断自动清洗流程 |
| RF 48V 电源 | 网口第8页 `0x32 RF 板48V电源开关` | 与 RF 24V 不合并、不自动联动 |
| 高压板电源 | 网口第8页 `0x33 高压板电源开关` | 不等同于 ESI 电压设定 |
| TD 温度设定 | 485 第5页 `0x02 TD 温度` | 编码范围不是安全温度范围 |

`VendorControlCatalog` 仅定义已知命令的数据区编码，不生成完整报文、不打开通信端口、不证明设备执行成功。没有文档依据的附加部件不新增；设备不支持或尚未接入的项不得显示为实机可操作。现有模拟适配器的显示仍须与真实设备区分。

## 必须确认的具体问题

1. **485 帧长度冲突**：第3-4页定义长度为两字节，第5页示例 `55 88 01 00 01 02 AA` 符合该格式；第8-9页灯/加热例子使用一字节长度。须提供适用固件版本与正确完整收发帧。封面 V1.1、历史 V2.0 和文件名 V2.1 也不一致。
2. **485 校验与应答**：帧表未列校验字段，但有“计算累加和”标注；应答表单字节 11/12 与后文双字节 11 00/12 00 并存；13/14 命令未列出对应应答。不能自选格式。
3. **串口连接**：第8页截图为 9600、8 数据位、1 停止位、无校验、无流控；这仅是示例，需确认现场设置及USB转485驱动。COM4不是应硬编码的端口。
4. **网口连接**：未给出可核实的 TCP/UDP、设备/主机角色、IP与端口等连接参数。
5. **网口 CRC/长度**：仅定义16位CRC及高字节先发，未给多项式、初值、反射与最终异或；第3页表格覆盖范围与第4页文字对帧计数是否参与CRC有歧义。后续命令长度的 `1+2` 等写法也需确认包含哪些字段，需厂家提供CRC代码或带CRC的有效完整帧。
6. **网口状态布局**：第13-14页表格列出多个独立开关字节，又列报警/ADC/版本；下方却写“数据区长度为9”及“第4位为高压、RF、隔膜泵状态”。须确定实际字段/位定义，不能混用。
7. **电压/真空换算**：485真空是0-3300mV原始值；网口也上传原始真空规数据，缺真空规型号与压力换算。网口ESI的控制值到实际高压、参数长度/倍率也需逐项确认；不能把ADC或控制电压直接显示成实际压力/高压。
8. **扫描数据解释**：网口第15页规定离子信息分帧上传，但不足以确定每采样点编码、扫描边界/序号、时间基准、MS级别及原始采样到m/z的校准映射。还需要一组原始报文和对应谱图/校准参数。
9. **方法/安全**：方法字段存在总长度/倍率/偏移不清楚的部分；报警表也标注未完整。需确认允许范围、互锁、启动/停止顺序、异常恢复和断线行为，编码范围不是安全操作范围。

## 对现有架构的影响

`src/device/IInstrumentAdapter.h` 已有 validateSetting / requestSetting / settingFinished / confirmedSettings 可承载白名单控制；超时为未知、不得假定关闭或盲目重试危险命令。实际控制须以回执和状态回读共同确认。

当前 acquireSpectrum() 是一次取谱接口；持续扫描不能只塞入一帧。后续宜增加有界异步扫描流，携带时间与MS级别，独立处理分帧重组、超时及背压，再交给现有 SpectrumScan / TIC / EIC 引擎。不能在UI线程等待串口或网口。

建议顺序：协议疑点确认 → 纯编解码与错误帧测试 → 厂家报文离线回放 → 只读连接/状态 → 经确认的单项控制 → 扫描/方法联调。未知字段保留未知，模拟适配器与真实连接始终区分。

给厂家最简索取清单：适用固件版本及接线方式；网口IP/端口/TCP或UDP；正确收发报文和CRC代码；状态字段表/换算公式；一段实际扫描报文及对应m/z谱图；设备安全互锁和启停顺序。
