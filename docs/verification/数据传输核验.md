# 导入、导出与低资源验证

## 用户入口

数据 → 检测记录：主要按钮“导入数据”，次要按钮“导出选中数据”。导入允许多选；导出先选择一条记录，再选择保存位置。进度、成功/重复/失败计数以及导出路径留在数据页。诊断移至“更多”，未删除功能。主页保留导入入口，服务首次使用而非重复新增一套功能。

支持本软件 `.qit.json` 原始数据归档；不声称能解析未知厂家的专有数据。PDF 仍在报告页生成，避免与原始数据导出混淆。

## 资源和完整性边界

- 一批最多 200 文件，单文件最多 64 MiB，超出时明确拒绝并提示分批/分段，不静默截断谱图或降低精度。
- 单工作线程逐个读取、校验、分析、事务保存；同一时间只保留一个归档的谱图，进度跨线程仅传小文本。SQLite 连接在线程内创建和释放，不共享主线程连接。
- 同一校验通过的 payload 和引擎版本对应稳定导入 ID，再导入会跳过；路径变化不导致同一归档重复保存。失败文件不阻塞后续文件。
- 停止请求在文件边界/分析后生效，当前事务不强杀；已完成记录保留。关闭程序等待当前工作安全结束，可能不是立即退出。
- 导出读库与写文件也在后台；QSaveFile 临时写入并提交，失败不截断原文件。文件对话框保留覆盖确认。
- 导入期间允许浏览，但阻止再开一批导入或开始检测；不改变当前分析结果，完成后从记录页双击打开需要的记录。
- 后台辅助连接不更新主会话的 clean_shutdown 标记；崩溃恢复语义不因工作线程退出而失效。

## 回归样本

WorkspaceTests 构造 200 个归档，每个 256 个原始点，导入共保存 51200 原始点及对应处理点；重复导入 200 文件后记录仍为 200。检查事件循环仍响应、限量读取、坏文件、过大文件、取消后 3 条记录重开可读、连接数量恢复、数据库完整性和主会话未退出标记。

UiSmokeTests 覆盖选中记录→后台导出→校验→双文件导入→重复跳过→按钮恢复，同时继续原有 PDF、方法激活、窄屏、聊天上限测试。

这些是可重复的有限样本，不等价于半年真实运行或百万张大谱图。实际 Win7 工控机的 CPU、SSD/磁盘容量、8GB 整机余量、掉电与硬件驱动仍需厂家验证。没有给出“任何文件大小都不卡”的保证。
