# QitVenture 功能核对与菜单分层

## 核对范围

本清单基于厂家安装包解出的两个 Windows 主程序静态核对：

- `QitVenture6_20260807.exe`
- `Scientz-qitest1.exe`

两个程序包含相同的主要 Qt 窗口/组件标识。安装包还带有定量窗口源码，能够确认定量模块的按钮与数据流程。静态信息可用于确认软件暴露过哪些功能，但不能替代真实 Windows 仪器联机测试，也不能证明某项厂家功能本身可靠。

## 厂家程序中确认存在的功能域

| 功能域 | EXE/附带文件证据 | 当前工作站归位 |
|---|---|---|
| 方法编辑与版本 | `EditMethodWindow`、`MethodSetWindow`、`.mth` 导入 | 顶部“编辑方法”；保存新版本、激活版本均为真实操作 |
| 运行与停止 | 运行方法、结束方法工具栏语义，`NO_RUN_METHOD_ERROR` | 顶部同一个“运行方法”按钮按状态切换为“停止方法” |
| 历史记录 | `HistoryDataWindow`、`HistoryDataToDisk` | “数据 → 检测记录”；支持恢复、导入、导出与诊断包 |
| 谱库 | `MassLibraryWindow`、`LibraryContents`、`Quan_SearchinLibrary` | “数据 → 参考谱库”；当前正式库只读检索，避免未经审计直接改库 |
| 定量 | `QuantifyWindow`、`QuantifyChromatographyWindow`、曲线拟合、结果计算、保存曲线、另存库 | “数据 → 定量曲线”；导入校准点后由本地确定性引擎拟合并显示 R² |
| 报告 | `UserReportWidget`、`createReport(bool)`、打印支持 | 顶部“生成报告”；人工复核后生成可追溯 PDF |
| 仪器状态 | `MonitorInfoWindow`、`GasPressureWindow`、多个 Dock | 顶部“仪器”只开关固定监控栏，不再跳转设置 |
| 仪器控制 | `InstrumentControlWindow`、`EquipmentControlWindow`、`InstrumentPresetWindow` | 顶部“设置”中的仪器配置；真实硬件写入必须由协议适配器和互锁确认 |
| 调谐/校准 | `MsCalibrateWindow`、`RF_AC_SettingWindow`、`RFWaveForm` | 设置 → 仪器配置 → 调谐与校准 |
| 进样系统 | `InjectPumpControlWindow`、`SyringeSetWindow`、`AutoSampleControlSetWindow` | 设置 → 仪器配置 → 进样与注射泵 |
| 升温/降温/电源 | `ShutDownProgressWindow`、`UserPowerWidget`、`icon_cool` | 设置 → 仪器配置 → 降温与关机；不放顶部，避免误触 |
| 载气与离子源 | 工具栏语义及仪器参数窗口 | 设置中的独立模块；AI 只能导航，模拟适配器才允许受控状态写入 |
| 清洗维护 | `extraction` 资源及外围设备窗口 | 设置 → 维护；按流程显示，不拆成多个顶部按钮 |
| 用户、权限、日志、帮助 | `UserControlWindow`、`UserPowerWidget`、`LogWindow`、`OperationManual` | 设置 → 账户与支持；锁屏属于会话保护，不占顶部入口 |
| 自动序列、样品分类、外围设备 | `AutoSequenceEditWindow`、`SampleCategoryWindow`、`PeripheralsListWindow` | 暂不新增入口；须先有明确业务需求、数据模型和仪器协议 |

## 最终一级菜单

一级只保留高频主流程、全局状态与重要管理入口：

1. 智能台
2. 主页
3. 运行方法（运行中原位变为停止方法）
4. 编辑方法
5. 生成报告
6. 数据
7. 仪器
8. 设置

“数据”是唯一组合入口，二级包含检测记录、参考谱库、定量曲线。仪器只负责实时监控；设置进入完整设置与维护。两者不再互相跳转或重复包含同一按钮。

## 不提升到一级的理由

- “结束方法”不是独立页面，而是运行状态下同一按钮的安全反向动作。
- 谱库和定量是重要但非每次检测必用的任务，放入数据二级菜单能减少顶部拥挤。
- 升温、降温、开关机、离子源、载气和清洗是低频或有风险的仪器动作，必须先看到当前值、边界和确认步骤。
- 锁屏是会话保护，不是检测任务；电池图标只显示供电状态。
- 厂家 EXE 中出现但当前需求没有明确要求的自动序列、云上传、GPS、样品分类等功能不因“厂家有”就加入。

## 点击验收门槛

- 每个一级入口必须产生唯一且可见的结果：页面切换、面板开关或运行状态变化。
- 每个二级入口必须打开有数据结构、状态或可执行流程的页面，不允许只有标题的空壳。
- 文件导入/导出必须处理取消、不可读、数据不足和成功四类结果。
- PDF 必须在自动测试中验证文件存在且以 `%PDF` 开头。
- 高风险动作不得由普通导航或大语言模型直接执行；真实仪器必须经过权限、协议适配器、互锁和人工确认。
- 每次交付运行顶部导航、数据二级菜单、仪器/智能台并行显示、采集状态切换和报告导出测试。

## 仍需真实硬件后补的边界

当前 Qt/C++ 工作站能完整运行模拟适配器、数据引擎、记录、谱库检索、定量拟合、报告和本地 AI 工具导航。仪器控制、调谐、进样、清洗、载气、离子源和电源页面目前不能视为真实硬件验收；正式接入时必须由厂家通信协议逐项替换模拟读写，并做故障注入、断连恢复和长时间稳定性测试。
