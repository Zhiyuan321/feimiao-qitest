# 分子泵共用485回读版

依据2026-09-09用户提供的Qt代码，仅发送以下四条ASCII查询，末尾为实际回车0x0D：

```cpp
"0010039802=?115\r" // 转速
"0010031002=?099\r" // 电流
"0010031302=?102\r" // 电压
"0010032602=?106\r" // 控制器温度
```

## 实机操作：同一页面、同一串口

用户确认分子泵与主控板共用COM口及相同参数：9600、8N1、无流控。

1. 设置 → 仪器控制 → 运行状态 → **485串口**。
2. 选择实际COM口，保持勾选“同时读取分子泵”，点击“连接并读取”。
3. 同一张表上方显示主控板温度、流量、气压和分子泵四项换算值（说明列保留原始值）；更多主控板参数向下滚动查看。
4. “导出485报文”保存主控板及分子泵的收发JSON，未读出数值或超时也可导出。
5. 点击“断开”统一停止两部分查询并清空读数。重新连接可以重新启用暂停的泵查询。

只有Rs485Instrument持有QSerialPort并读取readyRead，一次连接只打开一次COM口；PumpReader仅缓存原始值、换算值及诊断记录，不再创建串口。取消勾选可按原方式只查询主控板。启动后不会自动连接。网口继续独立工作。

## 已确认的换算（2026-09-09用户实机确认）

| 参数 | 换算 | 核对示例 |
| --- | --- | --- |
| 398 转速 | 六位十进制值直接作为RPM，不乘60 | 090002 → 90002 RPM |
| 310 电流 | 原始整数÷100，单位A | 000014 → 0.14 A |
| 313 电压 | 原始整数÷100，单位V | 002364 → 23.64 V |
| 326 温度 | 原始整数直接作为℃；控制器温度即泵体温度 | 000032 → 32.0 ℃ |

四项映射到仪器遥测；右侧监控显示转速和泵体温度。主控板刷新不会清除泵值；泵超时或断开后清空原始值与换算值。000000是有效零值，未收到不能显示为0。导出保留六位原始串及带单位字段名的换算值。

## 共用串口调度

- 查询顺序：主控板0x30 → 分子泵398 → 310 → 313 → 326 → 下一轮主控板。
- 一个查询得到匹配回复后，等待200ms再发下一个；同一时刻仅一个查询在等待回复。正常一轮约1秒加各设备响应时间，并非固件规定周期。
- 每项响应超时1.5秒。分子泵任一项超时：清空全部泵读数、暂停本次连接的泵查询，继续在同一COM上读取主控板，不自动重试泵请求；晚到泵回复不能恢复读数。
- 主控板查询超时或串口错误沿用关闭端口策略，清空两部分。主控板读数超过5秒未更新独立失效，不因分子泵回包刷新有效期；新主控板回复可恢复。
- 下一次查询前清空旧半帧及输入残留。二进制主控板帧与ASCII泵回复仅按当前查询所属协议解析，避免错配。

## 解析边界

- 按回车组帧，可处理半帧、多帧及回车后的换行。单帧缓存上限256字节，超长数据丢弃至下个回车。
- 仅地址001、已知参数编号、数值位置恰好六个ASCII数字才可成为试读值。
- 严格采用用户代码下标：参数`mid(5,3)`、原始值`mid(10,6)`。保留六字符（包括前导/末尾零），不猜其他偏移。
- 查询回显、非当前查询的参数和不符合取数条件的回复不更新读数。
- Word第7.1节回复示例`0010039812=?001200\r`在下标10会取到`=?0012`，与代码冲突，因此此示例会保留到日志但不能显示为数值。
- 回复校验码、完整长度/动作字段仍未确认：取数成功不等同于完整协议验证。单位倍率以上述用户确认为准，不改变泵运行状态、报警或启停互锁。
- 导出最近256条共享总线TX/RX字节块和超时事件，包含ASCII及hex；RX条目可能是半帧或多帧，不是完整帧计数。设备报文不提交仓库。

## 测试

`qitest_pump_tests`覆盖四条固定指令、原始值位置、四项确认倍率、零值和失效清空、错误回复拒绝、半帧/多帧/超长输入；同一内存串口连续两轮顺序轮询、仅打开一次、无重叠请求、主控/泵超时处理、迟到回复、主控读数有效期与共享日志导出。

`qitest_ui_tests networkPanelConnectsAlongside485`以一个共享内存串口和本机TCP，验证一个485入口同时显示两部分、端口仅打开一次、导出、停止清空及网口独立。1024×768截图检查表格和按钮可见。合成回复仅验证软件，不代表真实固件格式或校准。

Windows测试包使用Qt5.12.12/MinGW7.3 x64构建；最终以Win7实机收发日志验收。
