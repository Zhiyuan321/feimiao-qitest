# 本地工业智能台架构

## 不可改变的边界

> Qwen 理解意图与解释证据；C++ 决定能否执行、执行什么以及安全范围。

智能台不直接控制 QWidget，不直接写仪器协议，不向数据库任意发 SQL，不生成科学数值。所有操作都经过一个稳定、可测试、可替换模型的 C++ 桥。

## 执行链

```text
用户自然语言
  → 确定性别名路由（常用命令，毫秒级）
  → Qwen 意图补全（只在确定性路由不匹配时）
  → <tool_call> JSON
  → AiToolProtocol 解析、白名单和置信度检查
  → 角色 / 仪器状态 / 参数范围 / 风险检查
  → QAction / AppController / 领域引擎
  → 结构化执行回执
  → Qwen 用自然语言解释结果
```

## 数据分层

| 问题 | 唯一正确来源 | 不允许的替代 |
|---|---|---|
| 仪器现在多少度、是否就绪 | `IInstrumentAdapter` 实时状态 | Embedding / 历史文档 |
| 昨天的样本、方法版本、审计记录 | SQLite 结构化查询 | 向量相似检索 |
| SOP、错误码、参数含义、维修手册 | 本地知识库 + 检索 | 让 LLM 凭记忆回答 |
| 峰识别、匹配、定量、质量分数 | 确定性 C++ 科学引擎 | LLM 估算 |

## 当前工具白名单

只含页面导航和读取/准备类操作：主页、运行准备、记录、报告、谱库、方法、定量、仪器状态、仪器设置页、电源页、设置和帮助。

下列动作永不由模型直接执行：开始采集、停止真实采集、修改硬件参数、发布方法、删除/覆盖、标记阳性、完成正式复核、降温和关机。模型可带用户到达相应页面，显示 C++ 计算的范围和风险，由人工确认。

## 为什么不用 600 MB 大小判断 Embedding

`Qwen3-0.6B-Q8_0.gguf` 是旧的 6 亿参数对话模型，不是 Embedding。当前交付包只使用 `Qwen3.5-4B-Q4_K_M`。工具调用的稳定性来自工具协议、结构化校验、状态机、风险门和评测集，不来自 Embedding 文件的体积。

在 8 GB 设备上，知识库先用确定性中文字词检索；当手册量和召回评测证明必须引入向量检索时，再加一个小型、可替换、按需加载的 Embedding 适配器。它只服务文档检索，绝不参与硬件决策。

## 必须持续评测的指标

- 工具选择正确率与参数正确率。
- 多种口语表达、含糊请求和否定句的稳定性。
- 危险动作拒绝率必须 100%。
- 工具调用后实际页面/对象是否到达。
- 手册检索 Recall@k、引用正确率与幻觉率。
- 模型冷启动时间、峰值 RSS、界面帧延迟和超时回退。

更换 Qwen 或新增 Embedding 之前必须跑同一套评测；没有显著改善就不更换。

## 长期运行策略

- 智能台对话最多保留有界的可见记录，不让界面随数年使用无限膨胀。
- SQLite 使用 WAL、`synchronous=FULL`、事务写入、busy timeout 和 64 MB journal 限额。
- 工作区在打开时写入“未正常关闭”标记，正常退出后恢复；只有上次异常中断才执行数据库快速完整性检查。
- 采集会话独立记录开始/完成，启动时恢复中断会话；单次写入在一个事务内完成。
- 数量增长后用分页和有索引的条件查询，不把全部历史记录一次性创建成 QWidget。
