# 仪器内置端稳定性与简化操作契约

本文件是飞秒质谱工作站的工程硬约束。目标不是用按钮填满屏幕，而是在仪器中小尺寸屏幕上长期、稳定地完成海关筛查工作。

## 1. 操作层级

- 顶部左侧只放可随时展开的“智能台”。
- 顶部中央只放高频主流程：主页、运行方法、方法、生成报告，以及收纳记录/谱库/定量曲线的“数据”菜单。
- 顶部右侧只放“仪器”菜单和受控“电源”入口；降温归入电源流程，维护设置归入仪器菜单。
- 设置不是检测主流程，不与主页和运行方法争夺一级位置。
- 首屏不展示型号、开发框架、离线会话名等无操作价值的文字。
- 所有常用点击目标至少约 44 px；不得依赖只有鼠标悬停才能发现的关键操作。
- 空白是稳定布局的一部分，不用虚假指标、装饰卡片或无功能按钮填充。

## 2. 功能真实性

- 每个可见入口必须进入真实页面、读取真实本地状态，或明确说明缺少哪项正式协议/数据。
- 不用伪造科学数值填满页面；模拟数据必须保留模拟边界，不能形成正式鉴定结论。
- 科学计算、定量拟合、谱库检索、报告、AI 解释分别通过清晰接口工作，共享同一份检测记录和质量结论。
- AI 是可替换、可关闭的辅助层。AI 不可用时，采集、分析、记录、复核和报告仍可运行。

## 3. 长期运行边界

- UI 内存只保留当前谱图、当前结果和有界的智能台文本；切换记录时替换旧对象，不累积半年数据。
- 历史检测写入 SQLite；列表查询必须带 `LIMIT`，详细谱图只在用户打开单条记录时加载。
- SQLite 使用外键、WAL、`synchronous=FULL`、忙等待和自动 checkpoint；一次检测及其谱图、候选、质量检查必须在事务中完整提交或完整回滚。
- 启动时把未正常结束的采集会话标记为 `INTERRUPTED`，不得把中断任务伪装成完成。
- 数据默认不因性能原因自动删除。归档、备份和保留期由部署策略明确决定。
- 日志、AI 对话、缓存和内存队列必须有上限；新增集合时必须说明容量与清理策略。
- 8 GB 部署档默认使用 3.01 GB 的 Qwen3.5-4B Q4_K_M、4096 token 上下文、单并发 slot 和最多 12 条有界顺序队列；同条件三类请求后 llama-server RSS 实测约 3.53 GiB（Q5 约 3.90 GiB），整体常驻内存目标不超过 5 GB。超过预算时优先缩短上下文或暂卸载 AI，不挤占采集与持久化资源。
- 本部署档不加载视觉 `mmproj`；不以基础模型的多模态架构代替对实际交付功能的验收。

## 4. 发布门槛

- 每次交付必须通过科学核心、谱库、工作区、权限、AI 证据和 UI 主流程测试。
- 半年稳定性采用分层验证：持续集成中的六个月历史窗口回归、部署前长时间 soak test、真实仪器上的断电/磁盘不足/通信中断故障注入。
- 当前自动测试证明的是有界读取、持久化重开、异常采集恢复和主流程不崩溃；它不等同于真实仪器连续运行半年。
- 真实仪器发布前必须补齐协议适配器、硬件看门狗、磁盘空间报警、自动备份与现场恢复演练。

## 5. 性能原则

- 准确性和可追溯性优先，其次是稳定性，最后在不改变科学结果的前提下优化速度。
- 大谱图的采集、分析和导入不得长期阻塞 UI 线程；正式硬件数据规模明确后，按测得阈值迁移到受控后台任务。
- 不以“半年数据一次性载入”作为任何界面的实现方式；所有历史浏览采用分页或连续有界加载。
