## 已内置网口TCP首版

气压曲线在正常检测完成后保留最后一周期，不再因5秒未更新而清空；下一次有效检测请求被接受时清空旧曲线。关闭回执后的末帧仍可更新保留曲线。取消/失败不标记为正常完成，断开或重新监听仍清空，未新增历史文件气压回放。

2026-09-15整周期帧修订（替代旧版分包组谱规则）：现场0x81长度3252含两字节周期编号，数据3250字节/1625点，一帧就是一周期。0x81/0x82长度后的两个字节按16位大端周期号解释，从0递增；状态及命令ACK仍用原1/1字段。仅波形帧放宽到16位长度字段可容纳的最大偶数数据区65532字节，TCP可多次读取后组成一帧。按用户随后确认的旧软件行为，上传波形（action=0x20、command=0x81/0x82）只记录CRC收到值与计算值，不因不匹配而拒收；状态、心跳和控制回执仍严格检查CRC16/MODBUS（FFFF初值、高字节先传），包括action=0x10的0x81方法回复。帧尾与长度检查保留。质谱点数须匹配当前方法，质谱/气压分别检查采集期周期连续性；质谱时间=周期编号（秒），强度原值和TIC/EIC求和保持不变。导出包含CRC策略及不匹配累计数，记录兼容接收不等同于证明原始数据无误。

在“仪器控制 → 运行状态 → 网口TCP”点击开始监听（默认11000），设备主动连接电脑。读取倍增管电压、真空规原始值、换算后的真空度（mbar）和实验状态；可与485同时连接，分别失效。0x82气压按用户代码换算为V，暂按单包采样序号显示；射频页支持调谐启停。调谐是现场常规操作，不因本地会话角色隐藏，但开始前仍需二次确认，且只有有效网口状态、实验停止时才发送。Fullscan 方法在有效状态且检测停止时，通过网口0x81下发并等待应答。已接入 Fullscan 定时采集：使用参数预设中的检测秒数，开启/关闭均等待网口应答，完整周期帧校验后保存原始强度、TIC/EIC序列；当前不执行实机谱库筛查。详见 [网口首版接入说明](../../docs/integration/网口首版接入说明.md)。

## 文件职责

解析诊断：TXT/JSON另存解析前RX_RAW原始接收块（最近最多128块/1MiB），采集首次错误冻结当时原始窗口及长度/帧尾/CRC等判定依据，后续状态和心跳不会覆盖错误现场。重新监听或下次开始采集会清除相应错误现场；波形CRC按上述兼容策略记录，其他解析检查保留。网口0x30的11/12回包单独计数，不再计为未解析帧。

- PumpProtocol.* / PumpReader.*：按用户四条ASCII查询和固定位置取数的分子泵只读试验；按用户确认倍率显示RPM/A/V/℃，保留原始值与有限收发日志，回复校验仍待确认。同一个COM统一排队查询，在同一485页面显示。详见[试读说明](../../docs/integration/分子泵试读说明.md)。

- NetworkProtocol.*：TCP帧、CRC与21字节状态解码（2026-09-09修订，实验状态01/00）。2026-09-14用户确认Fullscan：冷却时间→data[8]，进样时间→data[13]（输入380下发380，不乘100）；data[20]/data[21]为独立组合，本版按旧抓包改为固定1/3000，不随冷却时间改变；data[25—44]固定尾部亦按旧抓包，其他可编辑项及datafit校准换算保持动态。周期总时间使用data[8]。本次确认整数直传，非整数进样时间仍拒绝，不擅自截断或推测小数编码。
- NetworkInstrument.*：TCP监听、同IP新连接接替旧连接、读数有效期、连接事件/原始帧导出与485并行状态。支持TXT十六进制文本及JSON；TX表示提交发送，不代表设备接收/执行成功，未知方法返回码按原值保存；16页版协议的0x29按冷却时间错误立即结束本次方法请求，不再误报无回传。

- Rs485Protocol.*：最新485协议帧与23字节状态解码。
- Rs485Instrument.*：单串口统一调度主控板/泵；泵超时暂停泵查询，主控超时或串口失败关闭。
- IInstrumentAdapter.h：宿主与驱动的公共接口。
- IInstrumentPlugin.h：插件工厂与 ABI 标识。
- SimulatedInstrument.*：模拟实现，用来理解调用顺序，不要复制其假数值到真实驱动。
- VendorControlCatalog.h：协议控制数据区与出处，**不包含完整报文/传输/CRC**。

## 最短联调顺序

1. 从 ../../examples/vendor_adapter 开始。插件用与宿主一致的 Qt、编译器和位数。
2. descriptor 返回实际型号且 simulation=false。
3. health / telemetry / confirmedSettings 返回工作线程维护的实际回读缓存；不要阻塞 GUI。
4. validateSetting 检查能力、连接、单位、互锁及厂家安全范围。
5. requestSetting 保存请求号，异步发送；收到实际状态后发 settingFinished。
6. 方法参数走 validateMethodParameters / requestMethodParameters。Fullscan 的基本设置依次通过 485 命令 0x02、0x13、0x12、0x04、0x14 下发，全部应答成功后再通过网口 0x81 下发质谱设置；任一拒绝或超时立即停止。离子源电压在现有 485 文档中没有写命令，非零值必须拒绝，不能挪用网口 ESI 高压命令。
7. 控制器要求 requestId、key、readback 对应原请求；超时不自动重发。
   操作界面仅在真实适配器完成上述回读链后显示“设置成功”；预览路径不会显示硬件成功提示。
8. 最后才联调高压、泵等危险动作，台架与设备互锁必不可少。

## 建议断点与日志

main.cpp 的插件加载 → AppController::updateInstrumentSetting → 驱动 requestSetting → settingFinished 回调。

## 启用插件

在 PowerShell 设置绝对路径后启动宿主：

```powershell
$env:QITEST_INSTRUMENT_PLUGIN = "C:\Dev\driver\QITestVendorAdapter.dll"
& "C:\Dev\app\飞秒质谱工作站.exe"
```

未指定插件或485串口时使用轻量预览；指定插件加载失败会报错退出，不会更换设备来源。
尝试连接485或网口时，端口打开或TCP建立都不触发数据源切换；收到并校验有效状态帧后才切换。切换后若断线只显示断线，不自动回到预览。
连接页只保留一个“预览”入口。内部记录继续使用独立数据范围，预览记录不能混作真实采集记录。
详细契约见 ../../docs/integration/VENDOR_INSTRUMENT_INTEGRATION.md。
对应 tests/InstrumentControlTests.cpp；这组测试通过不代表实机通过。

插件 ABI 已升级为 1.2；接口新增方法参数校验、异步请求和完整回读，宿主与插件必须同步重编译。

2026-09-15补充：当前内置用户本次 datafit.json 的 Fullscan 系数（a=0.00013517703930585604，b=5.882440951161457，c=8.575019905095814），同步用于方法质量数转电压及扫描电压反算m/z。采集记录保存系数及来源文件SHA-256快照；历史记录不重算质量轴。按旧代码，上限超过801/1001分别需要datafit_1000/datafit_2000，当前未提供则拒绝该量程的方法下发。Iosolate分组未启用。

2026-09-16停止兼容：关闭0x15/0x23在500ms内未回复时再发送一次（最多两条），原3秒等待期限不延长；等待关闭时不再发送新增心跳。关闭仍须收到成功回复，无回执/拒绝/断线均不报完成。重发后收到成功，保留3秒迟到回复隔离窗口，期间禁止下一次开启，避免无请求号的关闭ACK被误认成开启ACK。500ms是对照旧抓包约533ms的测试实现，尚待实机验证。0x50仅按用户授权重放已观察报文，不推断物理用途。
